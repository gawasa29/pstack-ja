# benny オートメーションの意図

## 自動化したいこと

1 つの Slack の不具合チャンネルで協調して動く、2 つの Cursor オートメーションが欲しいです。

### オートメーション 1: 不具合報告のトリアージ

- トリガー: 設定したソースの Slack チャンネルで、誰かが新しいトップレベルの報告を投稿したら、その報告に対してこのオートメーションを開始し、元のスレッドの座標を保ってほしい。
- 振る舞い: スレッドと添付を読み、報告を不具合かパフォーマンス問題、機能要望、質問やフィードバック、別ルートへの転送に分類し、ルーティングの前に、所有していそうなレイヤーをたどってほしい。
- トラッカー: 設定したトラッカーで重複を検索し、確信のある重複は更新し、明確に新規の不具合にだけチケットを作ってほしい。
- ツール: Slack のスレッド読み取りと返信の権限、設定したトラッカー連携、任意のルーティングマップ。
- 成果: ソーススレッドに、短い判定と `[benny:bug]`、`[benny:performance]`、`[benny:other]` のいずれかを付けた返信をちょうど 1 つ。不具合かパフォーマンスの印には、トラッカーの URL を含めてよい。
- 境界: このオートメーションがソースチャンネルにルートメッセージを投稿することは決してない。

### オートメーション 2: 確認済みの不具合の再現と修正

- トリガー: 同じ新しいトップレベルの報告、またはセットアップ中に選んだ別の対応トリガーから開始し、元のスレッドで信頼できるトリアージの印を待ってほしい。
- ゲート: 誰かが明確に修正を所有しているときは止めてほしい。既存の pull request かマージ済みのコミットが報告を直す可能性があるなら、競合する変更ではなく検証をしてほしい。
- 振る舞い: 設定した control アダプタと機能マップを使い、実際の UI を通して正確な症状を 2 回再現し、スクリーンショット、動画、読み取り専用の状態の突き合わせを取得してほしい。
- 修正: 既存の pull request は、上書きして書くのではなく検証してほしい。再現が確認できたら、範囲を絞った根本原因の修正を 1 回試み、テストが安ければ tdd を使い、影響範囲をスモークし、前後の証明が通ったときだけドラフトの pull request を開いてほしい。
- ツール: Slack のスレッド読み取りと返信の権限、リポジトリと履歴へのアクセス、ドラフト pull request の作成、設定したトラッカー、control アダプタ。
- 成果: ソーススレッド、または任意の運用スレッドに証拠と検証済みの結果、加えて任意でドラフトの pull request。更新は簡潔に。
- 境界: このオートメーションがソースチャンネルにルートメッセージを投稿することは決してない。

### 共通ルール

- ソースチャンネルとルートスレッドの座標は、実行の間ずっと不変にしてほしい。
- ユーティリティやデバッグ用の bot は、委任や修正の所有ではなく証拠として扱う。
- サブエージェントの助けは許すが、Slack に投稿させたり、Slack の資格情報を持たせたりはしない。
- このパック全体を、対象リポジトリの `.cursor/automations/benny/` にコミットしてほしい。ここの `SKILL.md` は直接のオートメーション指示であり、登録されたプラグインスキルではない。
- pstack は、`how`、`why`、`tdd`、`unslop`、必要な原則スキルといった共有の依存のためにだけ、対象リポジトリにコミットした `.cursor/settings.json` 経由で有効にしてほしい。
- 各ライブのオートメーションプロンプトは、コミット済みの運用ファイルを直接読んでほしい。プラグインのキャッシュパス、抜粋のコピー、スラッシュスキルの探索は望まない。
- ユーザーが所有する設定、機能マップ、ルーティングマップ、秘密は、パックの更新で上書きされないよう `.cursor/automations/benny/` の外に置く。
- チャンネルの座標、トラッカーのアクセス、control アダプタ、機能マップのどれかが欠けているか不確かなときは、両方のオートメーションをフェイルクローズにしてほしい。
- pull request はドラフトのみ。マージやデプロイはしない。

### 自分の設定

- ソースの Slack チャンネル: `<channel>`
- 任意の運用チャンネル: `<channel or none>`
- リポジトリと既定ブランチ: `<repo>`、`<branch>`
- トラッカー: `<type, team, project, labels, intake status>`
- ルーティングマップ: `<path or none>`
- トリアージの身元: `<slack identity>`
- control スキル: `<configured skill or adapter>`
- 機能マップ: `<committed same-repo path outside the copied pack, or behavior to paraphrase>`
- モデル: `<triage, reproduce, code, media review>`
- ステータスの絵文字文字列: `<seen, reproducing, reproduced, blocked, fixing, failed, pull request opened>`
- 予算: `<polling, verdict wait, follow-up, repro, rejection, fix>`
- 任意の bot トークン能力: `<none, file download, or editable operations status>`

[`configuration.example.yaml`](./templates/configuration.example.yaml) と [`feature-map.example.md`](skills/reproduce-and-fix-issues/references/feature-map.example.ja.md) から始めてください。このパックの外（たとえば `.cursor/benny/` の下）にコピーして埋めます。秘密の値はシークレットマネージャか環境に置きます。

## エージェント向け

人間は、Cursor にこのファイルを指定することでセットアップに入ります。見つけた benny のスラッシュスキルを探したり呼び出したりしないでください。

1. どのリポジトリでオートメーションを動かすかを聞く。
2. この `FOR_AGENTS.md` を含むディレクトリを、ソースパックとして扱う。
3. ソースパック全体を `<target-repository>/.cursor/automations/benny/` にマージする。
4. 宛先にしかないファイルをすべて保つ。無関係なファイルを削除したり、ユーザーが所有する設定、機能マップ、ルーティングマップを上書きしたりしない。
5. ソースが管理するパスに既存の宛先ファイルがあり、内容が違うときは、diff をレビューし、ローカルの編集を捨てずにマージする。所有が曖昧なら、置き換える前に止まって聞く。
6. コピーした `FOR_AGENTS.md` と `skills/setup-benny/SKILL.md` が対象リポジトリにあることを確認する。
7. `.cursor/automations/benny/skills/setup-benny/SKILL.md` を、対象リポジトリから直接読んで従う。

次のエントリを、対象リポジトリの `.cursor/settings.json` にマージしてほしい:

```json
{
	"plugins": {
		"pstack": { "enabled": true }
	}
}
```

無関係な設定とプラグインはすべて保ってください。既存のファイルが jsonc なら、コメントと有効な jsonc の構文を保ってください。

対象リポジトリを根にした新しいエージェントによる検証がほしい。pstack の `how`、`why`、`tdd`、`unslop`、benny が使う原則スキルが、プロジェクトスコープで解決することを確認してください。現在のセッションやユーザースコープのインストールから読み込まれたスキルは数えません。

プロジェクトスコープのプラグインが使えない、あるいは共有の依存が 1 つでも解決しないなら、止まって何が失敗したかを説明してください。`.cursor/automations/benny/skills/` をプラグインのマニフェストに加えたり、そのファイルがスラッシュスキルの一覧に現れると期待したりしないでください。

どちらかのオートメーションを有効にする前に、`.cursor/settings.json`、`.cursor/automations/benny/`、参照される秘密を含まない設定をコミットする必要があると伝えてください。私が明示的に頼むまで、オートメーションを作成・更新しないでください。

初回作成では、組み込みの `/automate` を、トリアージに 1 回、再現と修正に 1 回使います。最初のオートメーションのドラフトレビュー、承認、準備確認、Automations エディタへの引き渡しを終えてから、2 つ目を始めてください。

この意図と完成した設定を、各ドラフトに言い換えて入れてください。トリアージのプロンプトは `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読んで従う必要があります。再現のプロンプトは `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読んで従う必要があります。これらのリポジトリ相対パスは、オートメーションを動かすリポジトリにコミット済みだと `/automate` が確認してから使ってください。

既存のオートメーションには、`/automate` を使って調べたり更新したりしないでください。設定を検証し、コピーしたセットアップファイルにある簡潔なフィールドのチェックリストを使って、私が各オートメーションをエディタで直接編集できるようにしてください。重複は作らないでください。
