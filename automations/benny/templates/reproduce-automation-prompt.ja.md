# 再現オートメーションのプロンプト

> コピーしたセットアップワークフロー用の素材。`automate` が、コピーしたパックがオートメーションを動かすリポジトリにコミット済みだと確認したあと、この意図を組み込みの `automate` ドラフトに言い換える。

この実行では `.cursor/automations/benny/skills/reproduce-and-fix-issues/SKILL.md` を読んで従う。

設定の出どころ。このリポジトリ相対パスは、同じ対象リポジトリにコミットされているときだけ含める。そうでなければ、設定された値を言い換える。プラグインのソースやキャッシュのパスは決して使わない:

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成の意図は、これを設定済みのソース Slack チャンネルにおける新しいトップレベルの報告として説明する。設定済みのリポジトリ、既定ブランチ、issue トラッカー、control アダプタ、機能マップ、ドラフト pull request の能力を含める。

ソースチャンネルとルートスレッドのタイムスタンプは不変として扱う。どちらかが欠けている、または設定と一致しないなら、投稿せずに止まる。

このスレッドで、設定済みのトリアージ身元からのトリアージマーカーを待つ。`[benny:bug]` か `[benny:performance]` のときだけ進む。

再現を試みる前に、設定済みの control アダプタのスキルを必須にする。実際の UI を通して、判別力のある正確な症状を 2 回再現する。既存の pull request やコミットは、上書きして書くのではなく検証する。修正を試みるのは、再現が確認でき、運用ファイルの修正ゲートを満たした後だけ。

Slack に投稿するのは調整役だけ。子のプロンプトはすべて、`SendSlackMessage`、`PostToSlack`、`chat.postMessage`、その他すべての Slack への書き込みを禁じる。子は調査結果だけを返す。

ソースチャンネルにルートメッセージを決して投稿しない。
