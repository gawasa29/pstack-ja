# トリアージ・オートメーションのプロンプト

> コピーしたセットアップワークフロー用の素材。`automate` が、コピーしたパックがオートメーションを動かすリポジトリにコミット済みだと確認したあと、この意図を組み込みの `automate` ドラフトに言い換える。

この実行では `.cursor/automations/benny/skills/triage-issue-reports/SKILL.md` を読んで従う。

設定の出どころ。このリポジトリ相対パスは、同じ対象リポジトリにコミットされているときだけ含める。そうでなければ、設定された値を言い換える。プラグインのソースやキャッシュのパスは決して使わない:

```text
{{BENNY_CONFIG_PATH}}
```

トリガー:

```json
{
	"source_channel_id": "{{SLACK_CHANNEL_ID}}",
	"message_ts": "{{SLACK_MESSAGE_TS}}",
	"thread_ts": "{{SLACK_THREAD_TS_OR_EMPTY}}"
}
```

作成の意図は、これを設定済みのソース Slack チャンネルにおける新しいトップレベルの報告として説明する。

ソースチャンネルとルートスレッドのタイムスタンプは不変として扱う。どちらかが欠けている、または設定と一致しないなら、投稿も issue トラッカーへの書き込みもせずに止まる。

分類、添付のレビュー、原因の追跡、ルーティング、重複排除、トラッカーへの書き込み、最終判定は、コミット済みの運用ファイルが持つ。進捗メッセージは投稿しない。ソースチャンネルにルートメッセージを決して投稿しない。

Slack に投稿するのは調整役だけ。委任したワーカーは読み取り専用で、調査結果だけを返し、Slack のあらゆる書き込み操作を明示的に禁止される。

単一の判定は、設定済みのマーカーをちょうど 1 つ付けて終える:

```text
[benny:bug]
[benny:performance]
[benny:other]
```

不具合かパフォーマンスのマーカーには `tracker=<URL>` を足してよい。
