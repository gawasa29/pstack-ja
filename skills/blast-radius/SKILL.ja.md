# 影響範囲（Blast radius）

変更が出荷される前に、その変更が別の場所で何を壊すかを見つけます。「X の影響範囲は」「これは何を壊しうる？」「まだ信用していない小さな diff のレビュー」に使ってください。

`how` と `why` の相棒です。`how` はコードが何をするかを教えてくれます。`why` はなぜその形なのかを教えてくれます。影響範囲は、その変更が別の場所で何を壊すかを教えてくれます。

呼び出し側を列挙するのが仕事ではありません。それならエージェントが 1 秒で grep できます。仕事は、grep では見えない壊れ方です。

## 自分のレポートを信用しない

もっともらしく聞こえる影響範囲のレポートは無価値です。それが正しくても間違っていても、読む側には説得力があるように読めてしまいます。だから、そのレポートをそのまま返してはいけません。全体が依存している 1〜2 個の事実を見つけ、コードを実行して証明します。

### どれくらい確かなのか

変更の安全性が依存する事実のそれぞれについて、安く済む範囲でこのリストのできるだけ下まで進め、どこで止まったかを言います。

1. 自分がそう言った。それだけでは無価値です。
2. その行を指し示した。実際の `file:line`、またはライブラリ自身のソースです。
3. 悪いケースが起こりえないことを示した。失敗を 1 ステップずつたどり、そこに到達しないことを確認しました。
4. 実際に実行した。本物のコードを呼び、間違っていれば大きく失敗するスクリプトかテストです。
5. 動いているアプリの中で再現した。

ステップ 4 はたいてい、アプリが出荷しているのと同じライブラリを import し、気にしている関数を正確に呼ぶ小さなスクリプト 1 本です。

## 手順

1. 変更を読みます。diff、その diff が追加・変更・削除するシンボル、そして今は何を違うやり方で行うのか。diff が明示していない部分も含めます。PR とコミットを取得するには `why` のステップ 2 を使ってください。
2. その変更が安全である根拠となる 1 つの事実を見つけます。危険に見える変更のほとんどは、1 つの事実のおかげで安全です。たとえば「この呼び出しは既に死んでいるキャッシュエントリを捨てるだけで、他には何もしない」というものです。その事実を見つけてください。それが成り立てば、危険に見えたケースのほとんどが一度に片付きます。時間を使うのはここです。「かもしれない」の長いリストではありません。
3. grep が止まる場所を見ます。呼んでいるライブラリのソースを読み、固定しているバージョンとローカルのパッチを確認します。いつ何が動くのかを突き止めます。マイクロタスク、アンマウントと teardown、Solid と React の違いなどです。シンボル検索が見落とすものを追います。API が返す JSON、DB のカラム、ワイヤーフォーマット、同じバイト列を読む別の言語、フィーチャーフラグ、3 ホップ下流のコードです。
4. 各リスクについて正直に書きます。実際に起こりうる可能性と、起こったときの実際のコストを示します。確認したリスクは残します。調べて問題なしと判断したものは別に並べます。ルールは `why` と同じです。実際の `file:line` を引き、何も見つからない検索も答えとして書き、呼び出し側や API をでっち上げてはいけません。
5. その 1 つの事実を証明します。本物のコードを実行するスクリプトかテストを書き、実行し、何が起きたかを貼ります。
6. 大きく広い変更なら、`arena` として走らせます。複数のモデルに同じ問いを投げ、答えを統合します。違うモデルは、それぞれ違う本物のバグを捕まえます。

## 返すもの

- **何をするか。** 何が変わったか。自明でない部分も含めます。
- **安全の根拠となる 1 つの事実。** それを述べ、どのステップまで進めたかを言い、証明を示します。証明できなかったなら、unproven と書きます。
- **リスク。** それぞれについて、どう壊れるか、`file:line`、どれくらい起こりやすくどれくらい悪いか、どう確認するかを書きます。重要なものには証明を貼ります。
- **問題なしとしたもの。** 何を調べ、なぜ問題ないかを書きます。
- **マージする前に。** 本物のバグを捕まえる最も安いテストか再現。書いたスクリプトも含めます。

`unslop` を通して書き、実際のコードを引き、公開される場所へ出す前に private なものをすべて取り除きます。

**返答:** 上のレポートを返します。安全の根拠となる 1 つの事実は、証明済みか unproven のどちらかにします。
