# 見きわめる（Figure it out）

タスクがどのプレイブックにも当てはまらないときは、プレイブックを自分で設計します。コードより先に届ける成果物は、ワークフローそのものです。タスクに合わせて厳格さを調整し、科学的方法を回し、人間が離席したあとに監査できる決定の証跡を残す、フェーズの並びです。

## 開始

最初の項目が **poteto-mode** スキルの Principles セクションを読むことである todo リストを開きます。そのあと、下のフェーズを todo として追加します。

## フェーズ A: 枠を決める

まず土台を固め、それから決めます。次のことを言えるようになるまで、実行を始めてはいけません。

- 反証可能な述語としての完了条件（**prove-it-works** 原則スキル）。
- 定量化したスコープ。おおよそのユニット数と工数、そして土台を固める中で表面化したブロッカー。
- 厳格さのレベル。高めに寄せます。一方通行のドアと影響範囲の大きいものには多く、可逆で賭け金の低いステップには少なく。厳格さとはゲートと成果物であり、「もっと頑張る」ことではありません。

長い実行に踏み切る前に、枠組みとトレードオフを提示します。可逆な作業は進めます（**never-block-on-the-human** 原則スキル）が、数時間に及ぶ実行ならチェックポイントを 1 つ得られます。

## フェーズ B: ワークフローを設計する

原子的で、独立して取り込めるユニットに分解します。最も危険な未知を先に置きます。足場と検証は機能より先です（**foundational-thinking** 原則スキル）。

- 作業より先に検証ハーネスを作り、変更前の状態からベースラインを取ります。チェックが「古い値 対 新しい値」として読めるようにするためです。
- 一方通行の設計判断には **architect** スキルを実行します（内部で **arena** を回します）。形がすでに具体的な機械的な作業では飛ばします。固まった設計に対してもう一度 arena を回すのは過剰設計です（**laziness-protocol** 原則スキル）。
- 何を並列に展開するかを決めます。並列化するのは継ぎ目をまたぐ場合だけにし、ワーカーごとに専用のワークツリーかブランチを与えます（**separate-before-serializing-shared-state** 原則スキル）。展開しすぎてはいけません。サブエージェントごとの推論レベルと、fast か standard かの速度は、**poteto-mode** スキルの Subagents セクションに従い、作業に合わせて選びます。
- 設計したフェーズのリストを書き留めます。人間がレビューするのはそのリストです。

そのうえで設計を実行します。そのステップを、フェーズ C とフェーズ D の項目の間に、具体的な項目として todo リストに追加します。各ステップはフェーズ C のループの規律のもとで実行し、フェーズ D のログをそこに織り込みます。証跡を最後まで取っておくのではなく、各ステップが着地するたびに 1 行記録します。

## フェーズ C: ループを回す

各ユニットは実験です。仮説を述べ、最小の変更を加え、実際の成果物の上で述語に照らして測ります。前進したなら残し、しなかったなら取り消します。**sequence-verifiable-units** 原則スキルを適用し、チェックを最後にまとめるのではなく、次のユニットを始める前に各ユニットを検証します。

- 検証は成果物を実際に調べて行い、自己申告で行うことは決してありません。何かが簡単に通りすぎるときは、システムより先に観測方法を疑います。
- 委任した作業には判定役を付けます。ワーカーがゲートを潜り抜けるなら、リセットして契約を厳しくします。ゲート自体が誤っているなら、回り道をせず、ゲートを独立した変更で直します。
- 判定は VERIFIED、NOT VERIFIED、INCONCLUSIVE のいずれかです。INCONCLUSIVE は合格ではありません。否定的な結果を隠してはいけません。

## フェーズ D: 監査証跡を保つ

実行は **show-me-your-work** スキルで記録します。figure-it-out の作業は、たいていレビュアーが PR で読めるよう証跡をコミットするのに十分な野心的さです。証跡と diff が揃って初めて、人間は戻ってきて作業を信頼できます。

## フェーズ E: 検証して引き渡す

ハーネスだけでなく、実際の製品の上で、全体をフェーズ A の述語に照らして確認します。繰り返し出てくる修正は、ゲート、lint ルール、チェック、スクリプトとして仕組みに埋め込みます（**encode-lessons-in-structure** 原則スキル）。

**返信:** 設計したプレイブック、厳格さのレベルとその理由、決定の証跡のパス、述語に照らして検証済みのもの、まだ開いているもの。
