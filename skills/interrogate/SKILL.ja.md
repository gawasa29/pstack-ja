# 尋問する（Interrogate）

敵対者が変更や設計を壊しにかかります。所見（finding）は、実行が証明したものだけが生き残ります。所見を報告します。修正は適用しません。

## 枠組み

範囲はユーザーが名指ししたものです。無ければ、ベースブランチとのマージベースからワークツリーを含む現在までのブランチ diff です。意図は **in-your-own-words** スキルで、ユーザーのメッセージ、コミット、PR の説明から述べます。意図が不明瞭ならユーザーに尋ねます。

## 横に広げる

**arena** スキルの Phase A のステップ 3 と 4、および Phase B を、4 つの変更で実行します。`arena runners` の代わりに `interrogate reviewers` 行を読みます。範囲の未コミット変更を各ワークツリーにコピーします。敵対者をそれぞれ `generalPurpose` として立ち上げます。arena のタスクと根拠の代わりに、各敵対者に範囲、意図、次のブリーフを渡します。

> この変更を壊してください。所見はそれぞれ、実コードに対する実行で証明してください。失敗するテスト、再現スクリプト、誤った振る舞いを示すコマンド出力などです。設計や計画なら、試作を走らせるか、現在のツリーを調べてください。再現は自分のワークツリーに置いてください。所見はそれぞれ、タイトル、正確なコマンド、それが出力したもの、意図が要求する出力とともに報告してください。実行していないものは省いてください。スタイル、命名、構造、将来の変更が無いと問題にならないリスクは、そうやって省いてかまいません。所見が無いことも有効な結果です。

## 検証する

arena の Phase F に従い、各所見のコマンドを再実行して検証します。出力が失敗を示し、その失敗が意図を壊すときだけ所見を残します。残りは落とします。同じ根本原因を共有する所見は統合します。

arena の Phase C、D、E は省きます。敵対者はそれぞれ別の失敗を見つけるので、判定は検証済みの所見をすべて保ちます。1 人の敵対者のリストではありません。

## 出力

- **意図**: 言い換えたもの。
- **所見**: 検証済みの所見それぞれについて、コマンド、その出力、どう意図を壊すか、見つけた敵対者。生き残りが無いときは "no verified findings" と述べます。
- **落としたもの**: 敵対者ごとに、落とした所見の数と理由。
