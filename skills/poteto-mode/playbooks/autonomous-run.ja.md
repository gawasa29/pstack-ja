### 自律実行（Autonomous run）

**終了条件はあなたが持ちます。完了を定義し、止まらずにそこまで駆け抜けてください。**

1. 最初の反復の前に、終了条件を検証可能な述語として明示します（テストがグリーン、再現が直っている、N 本の PR がすべてマージ済み、ピクセル diff がゼロ、など）。
2. 起床の仕組みは Cursor の `/loop` コマンド（pstack のスキルではなく組み込み）で選びます。監視するイベント（CI、マージ、ref の前進）があるなら、そのイベントであなたを起こす監視サブエージェントを置き、保険として長めの時間ベースのハートビートを併用します。イベントが無いなら、結果を再確認する価値があるタイミングに合わせた固定間隔のハートビートにします。サブエージェントごとに、その作業に合った推論レベルと、fast か standard の速度を選んでください（Subagents セクション参照）。
3. 各反復では、証拠が正当化する最小の変更だけを行い、述語に照らして検証し、前進したならコミットし、役に立たなかった変更は捨てます。「効くかもしれない」程度の保険は、様子を見ずに巻き戻します。
   作業は **sequence-verifiable-units** 原則スキルに従って並べ、最後にまとめて検証するのではなく、各単位を次に進む前に検証します。
4. 実行中に見つかった、ゴールに資する問題はあなたが引き受けます。壊れたスキル、関連するバグ、フレーキーな検証、レビューのノイズ、ツールの不具合、取り残されたフォローアップ、直せるドリフトは、poteto-mode 経由で自分で対処してください。本筋から外れた修正は、それぞれ独立した PR にします。可逆な作業を人間に預けて止めたり、`AskQuestion` を使ったりしないでください。表に出すのは、不可逆な操作、実験では決着できない本当のプロダクト判断や好みの判断、そして本当の行き止まりだけです。述語を主軸に据えたまま、脇の修正のたびにそこへ戻ります。
5. 反復ごとに **show-me-your-work** スキルでチェックポイントを残します。何が変わったか、述語が動いたかを1行にします。
6. 述語を満たしたら止めます。頭打ちは停止理由ではないので、続けたままアプローチを変えて押し越してください。空回りするより、本当の行き止まりを表に出します。勝利を宣言するために述語を緩めることは決してしません。

**返信内容：** 終了条件、実行した反復回数、取り込まれたもの、捨てたもの、最終的な述語の状態。
