### リファクタリング（Refactoring）

**契約はあなたが持ちます。構造は変わり、振る舞いは変わりません。** 振る舞いを足す Feature と、それを正す Bug fix とは別物です。

片付けの途中で欠けている機能や本物のバグが見つかったら、切り分けて、固定した契約に対して構造の変更を先に出荷します。作り直しは許されますが、そう名指しして Feature に振ります。大規模または横断的な構造作業は **figure-it-out** スキルの担当です。このプレイブックは、焦点の絞れた中規模までの変更を扱います。

1. まず振る舞いの契約を固定します。影響を受けるサブシステムに対して **how** スキルを実行して契約を学び、構造を動かす前に、現在の振る舞いを捉える特性テスト、スナップショット、等価性ハーネスのいずれかを書きます。その領域にテストが無いなら、構造に触る前に固定を書いてください。型チェックと lint は固定ではありません。
2. コードに欠けている構造を **principle-model-the-domain** に従って名指しします。形がすでに明確で局所的なら、地味なコードのままにします。作り直しは分岐や不正な状態を消すものでなければならず、間接参照を増やすものではありません。
3. 目標の形を名指しします。今日作るならモジュール構成、型、呼び出しグラフがどうなるべきかを述べます（**principle-foundational-thinking**、**principle-redesign-from-first-principles**）。目標が関数の境界をまたぐなら、動かす前に **architect** スキルで形を並行して探ります。
4. 足す前に引きます。新しい形を入れる前に、死んだコードを消し、呼び出し元が1つだけのラッパーを畳み、重複したバリデータを落とし、孤立した参照を取り除きます（**principle-subtract-before-you-add**）。目標の形に届く最小の変更だけを出荷します（**principle-laziness-protocol**）。「効くかもしれない」思いつきの片付けは巻き戻します。
5. 振る舞いを保つ小さな手順で動かし、各手順で固定をグリーンに保ちます。API の作り直しでは、同じ波の中で全呼び出し元を移行し、古い API を削除します（**principle-migrate-callers-then-delete-legacy-apis**）。互換シムは作らず、新旧並行の経路も作りません。リネームは必ず実ファイルに照らして抜き打ちで確認します。リネームは文字列、文章、後方参照の中の使用を黙って取りこぼします。機械的な編集は、設定済みの refactoring モデル（既定は `grok-4.7-xhigh-fast`）を使うサブエージェントに、範囲を具体的に指定して委任します（ファイルパス、移す名前、保つ振る舞い）。サブエージェントごとに、その作業に合った推論レベルと、fast か standard の速度を選んでください（Subagents セクション参照）。
6. 振る舞いが変わっていないことを、本物のアーティファクトで証明します。「コンパイルが通る」では足りません（**principle-prove-it-works**）。大きな作り直しでは等価性チェックを回します。新旧の出力を diff するスクリプト、記録したベースラインを新しいコードで再生する、関連する制御スキルで対応するサーフェスをスモーク実行する、のいずれかです。
7. その変更が残す価値があるかを確かめます。成功の尺度は読み手の負荷が減ったことです（**principle-minimize-reader-load**）。diff がどこかで読み手の負荷を下げていないなら、巻き戻します。
8. 小さく順序立ったコミットにリベースします。削除のコミット、次に作り直し、その後に続く片付けです。**sequence-verifiable-units** 原則スキルで形を整え、振る舞いを保つ各スライスが次へ進む前にグリーンであるようにします。**Opening a PR** を実行します。

**返信内容：** 変わった構造、突き合わせた固定、等価性の証明、読み手負荷の差分、出荷したものと巻き戻したもの。新しい振る舞いはありません。
