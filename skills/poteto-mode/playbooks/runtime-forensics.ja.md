### 実行時フォレンジック（Runtime forensics）

**診断はあなたが持ちます。ソースから理屈を組み立てず、動いているプロセスに計測を仕込んでください。** 成果物は引用付きの診断であり、修正ではありません。

1. 対応するサーフェス上で、制御スキルを使ってライブの信号を取得します。回り続けるプロセスなら CPU プロファイル、リークならヒープスナップショット、表示の不具合なら CDP トレースです。推測ではなく、本物のアーティファクトを取ります。
2. アーティファクトを決め手まで絞ります。ホットパス上の関数、リークしたオブジェクトから GC ルートまでの保持チェーン、入力なしに回り続けるループ、といったものです。大きなアーティファクトの解析はサブエージェントで行い（**guard-the-context-window** 原則スキル）、絞り込んだ所見だけをメインスレッドに残します。サブエージェントごとに、その作業に合った推論レベルと、fast か standard の速度を選んでください（Subagents セクション参照）。
3. 信じる前にメカニズムを証明します。動いているプロセスへの CDP eval で計測を注入するか、リロードせずにライブのコードを当て直して、仮説を安く確かめます。
4. 所見をソースに戻します。ファイル、シンボル、確保やスケジュールを行っている行です。
5. スループットのチェックポイントは1行のままです。`throughput checkpoint: n/a, read-only forensics`。

**返信内容：** 取得した信号、絞り込んだ所見、メカニズムの証明方法、ソースの位置、アーティファクトのパス。頼まれない限り修正はしません。原因が分かったら Bug fix か Perf に引き戻します。
