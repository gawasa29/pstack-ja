### セッションの引き継ぎ（Session pickup）

**再開点はあなたが持ちます。前の足跡を読み、やり直さないでください。**

1. 前の足跡を探します。アクティブなワークスペースの `agent-transcripts/` ディレクトリにあるローカルトランスクリプト（パスはシステムプロンプトに書かれています。`~/.cursor/projects/*/` をまたいで glob しないでください。ワークスペースの境界を越え、無関係なプロジェクトのプライベートなチャットを読むことになります）、クラウドエージェントの URL、push 済みのブランチのいずれかです。まずメタデータの概要と最後のメッセージを読み、そこから決定点をたどって遡ります。長いトランスクリプトの解析はサブエージェントで行い、絞り込んだタイムラインだけをメインスレッドに残します（**principle-guard-the-context-window** スキル）。サブエージェントごとに、その作業に合った推論レベルと、fast か standard の速度を選んでください（Subagents セクション参照）。
2. 運用状態を再構成します。ブランチとワークツリー、すでに取り込まれたもの（base に対する `git log` と `git diff`）、開いている todo、下された決定です。前の足跡は信頼できる入力です。それを導き直したくなる偏りに抗ってください。
3. 済んだことと未着手を diff します。出荷済みのものと計画を比べ、再開点を名指しし、前の再現を再実行したり完了済みの作業をやり直したりしません。「一から検証し直そう」というパスは、信頼できるはずの足跡を信用していないということです。
4. 残った作業を対応するプレイブックに振り分け、どう締めるかを選びます。実行を続ける、完成した推奨を出荷する、前の結論を追認するか覆す、失敗した実行を事後検証する、のいずれかです。引き継ぎのプレイブックはここで終わりです。以降は振り分け先のプレイブックが持ちます。
5. 引き継いだ主張を、元のゴールに照らして本物のアーティファクトで検証します（**principle-prove-it-works** スキル）。前の自己申告が通っていたことは証明になりません。

**返信内容：** 前のエージェントがどこで止まったか、引き継いだものとやり直したもの（やり直しが無いのが理想）、再開点、結果。
