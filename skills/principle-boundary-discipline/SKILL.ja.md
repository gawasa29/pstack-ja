# Boundary Discipline

バリデーション、型の絞り込み、エラーハンドリングはシステムの境界に置きます。内部のコードは無条件に信頼します。ビジネスロジックは純粋関数に置きます。外殻（shell）は薄く、機械的に保ちます。

**なぜ:** 散らばったバリデーションはノイズが多く、重複し、安全だという誤った感覚を与えます。ロジックをフレームワークの配線から出しておけば、フレームワークなしでテストできます。

**パターン:**
- **境界（CLI 引数、設定ファイル、外部 API、ネットワークプロトコル）:** バリデーションし、エラーを返し、防御的に扱います。
- **システムの内部:** 型付きのデータ、エラーの伝播、再バリデーションはしません。型を信頼します。
- **境界をまたぐとき。** 境界側の内部表現ではなく、ドメインの概念を公開します。汎用の仕組みは内側に、専用のポリシーは端に置きます。

**適用:**

バリデーションとエラーハンドリング:
- 設定はパース時（境界）にバリデーションし、ビジネスロジックの内部ではしません
- 生のデータは境界でドメイン型にパースします
- トランスポート、ストレージ、フレームワーク、ワイヤーの型を公開面から再エクスポートしません
- 境界がすでにバリデーション済みなら、呼び出しの深いところで冗長な nil チェックをしません

コードの構成:
- ビジネスロジックはフレームワーク依存のない純粋関数に置きます
- パース関数は、生のバイト列から型付きの状態への純粋な変換にします
- プロンプト構築は、構造化された状態を入力、文字列を出力とします
- スコアリングと評価は、状態から結果への純粋な変換にします

**テスト:**
- 「いまこのデータはシステム境界を越えているか？」越えていないなら、バリデーションは冗長です。
- 「これを、外殻がただ呼ぶ純粋関数にできるか？」できるなら、切り出します。
