# Fix Root Causes

デバッグでは、表に出た場所ではなく、障害そのものを直します。症状とは、誤った状態が見えるようになった場所です。根本原因とは、システムがすべきでないことを最初に行った場所、または扱うべき状態を扱えなかった最初の場所です。

**なぜ:** 症状を直すと証拠が隠れ、障害は別の場所で表に出る自由を得ます。そうするたびにシステムは推論しにくくなります。コードが、誰も名指ししていないバグへの回避策を抱えるからです。

**パターン:**
- まず再現します。
- 各ステップで「なぜ」を問い、答えがコード内の誤った判断になるまで続けます。以前の判断の結果で終わらせません。
- 詰まったら計測を仕込みます。実際のエラーと実際の状態を読みます。推測しません。
- 症状を引き起こした状態が正当かどうかを問います。システムがその状態になりうるなら、そこで壊れたコードが根本原因であり、そこで状態を扱うことが修正です。その状態が決して存在すべきでないなら、壊れた場所のチェックはバグを隠します。その状態を生んだものを探します。ガード、リトライ、握りつぶしたエラー、クランプした値、捨てた状態は、バグを隠すいつもの手口です。
- 再起動の後にだけ失敗するなら、まず永続化された状態を疑います。設定ファイル、キャッシュ、ロックファイル、シリアライズされた状態です。
- 1 つの事例ではなくパターンを探します。同じ障害のある場所をすべて見つけ、すべて直します。
- 回避策を正当化するのに段落ほどのコメントが要るなら、コードが間違っています。コメントではなくコードを直します。
- 決め手の事実を見つけるのに深く掘る必要があったなら、最初に見れば示せた、安価で常時オンのシグナルを提案します。
