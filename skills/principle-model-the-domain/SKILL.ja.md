# Model the Domain

本当のドメインを、条件分岐に散らばらせるのではなくデータ構造にエンコードします。ドメインに合う構造は、不正な状態を表現できなくし、分岐を消します。書くときに選ぶのは安く済みます。後から取り戻すのはリファクタに見え、先送りされます。

次の構造に寄せます:

- 散らばった boolean、フェーズ、ライフサイクルチェックの代わりに、状態機械。
- 緩い引数や繰り返される形の仮定の代わりに、型付きモデル。
- ファイルをまたいで散らばる分岐の代わりに、マップ、レジストリ、ルックアップテーブル、判別可能ユニオン。
- 場当たり的な状態変更の代わりに、reducer やコマンド / イベントモデル。
- load、validate、transform、save のような順序ではなく、1 つのドメイン知識を中心に組織されたモジュール。実行順序は所有権ではありません。
- 繰り返される振る舞い、所有権、不変条件を集める、小さなモジュール境界。
- アクセスパターンが求めるなら、キュー、キャッシュ、インデックス、グラフ、木、正規化されたコレクション。
- その他、合う構造。どれも合わないときは、コードが決して許してはいけないものと、データがどう読まれるかを明らかにし、それを正確にエンコードする構造を探します。

抽象化を無理に押しつけません。現在の形がすでに明快で、局所的で、育ちそうにないなら、退屈なコードを選びます。分岐、重複したルール、不正な状態、ライフサイクルのリスクを取り除かずに間接参照だけを足す抽象化には懐疑的になります。

この原則を飛ばした兆候は、既存の if/else の連鎖を分岐 1 つ分だけ育てる新機能、あるいは 1 つ目と同期し続けなければならない 2 つ目の boolean です。時間的分解も兆候です。フェーズ名のモジュールは、同じドメインルールをステップをまたいで繰り返します。
